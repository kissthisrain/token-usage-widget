# v0.1.7 发布说明

> 新增 WorkBuddy（本 agent）数据源；修复 ZCode 当天用量虚高、以及「立即刷新」对本地记录源无效的问题。

## ✨ 新增

- **WorkBuddy（本 agent）数据源**：自动探测并实时统计 WorkBuddy 本 agent 的每轮模型请求用量（读取 `~/.workbuddy-ai/projects/**/*.jsonl` 的 `providerData.rawUsage`），零配置、随会话实时汇入，支持趋势与模型明细

## 🛡️ 修复

- **修复 ZCode 当天用量虚高**：权威回填按天整体替换时会清空去重水位，导致启动时 rollout 全量重读把已计过的请求再累加一遍（实测 46M → 79M）；现改为整体替换时把水位钉到 sqlite 覆盖上界，并让增量累加与增量回收共用同一套去重口径
- **修复「立即刷新」对本地记录源无效**：此前该按钮只驱动在线源，对 ZCode / Codex / DSH / WorkBuddy 等本地记录源毫无作用；现在会真正触发本地源增量扫描与 ZCode 权威回填
- **修复同一批内同毫秒请求被漏计**：去重水位改为「整批处理完再推进」，避免同一毫秒内的多条请求被误判为重复
- **启动更稳**：创建窗口失败时退避重试 3 次，仍失败则给出明确提示并退出，不再留下「无窗口但仍在后台运行」的僵尸进程占着 WebView2 目录

## ⚠️ 已知限制

- OpenAI 用量接口需组织管理员 Key（普通 Key 返回 403）
- 「本地记录」与「OpenAI 官方」同时统计同一提供商时会重复计数，建议二选一
- OpenCode Go 官方额度依赖登录 Cookie，会话过期后需重新获取
- WorkBuddy 的 `prompt_tokens` 为每轮的完整上下文，多轮工具循环会重复计入（行业标准口径），总量偏大属正常
- 本地记录源仍以「最大时间戳」去重，跨批次同毫秒或乱序到达的记录理论上可能被漏计；由于 sqlite 为权威源并按天整体替换，少计部分会在下一个回填周期（≤5 分钟）自动纠正
